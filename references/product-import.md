# 自定义形象制作完成后导入产品

本指南核对吐梨邦当前的本地 2D 外观导入契约（2026-10-14）。其他产品或后续版本先核对目标契约，再转换。制作和预览、外观库登记、换上外观、实际桌面播放分别记录结果；用户已授权制作并应用时继续完成这些步骤。

## 将技能输出转换成可导入材料

技能的 `manifest.json`、`clip.json` 和 `index.html` 是制作/预览格式，不能直接选择它们导入。保留原始付费图、已验收动作和原始帧序列，在独立交付目录建立**数据型 `character.json` 加透明 PNG 帧**，或经目标产品验证的 `.petappearance`。不为格式转换重新生图。

当前本地导入器接受文件名为 `character.json` 的描述符，帧路径相对于该文件所在目录。例如仅含待机的最小包：

```json
{
  "name": "我的小猫",
  "anim": {
    "idle": {
      "dir": "idle", "base": "frame", "count": 1,
      "ext": "png", "start": 0, "pad": 2,
      "fps": 12, "loop": true, "face": 1, "idleBreathing": false
    }
  }
}
```

对应实际文件 `idle/frame00.png`。有更多帧时依实际序列设置 count/start/pad，不引用原图集或把一张图伪装成完整走路动作。最小包可验证导入，但不代表基础动作已全部完成。

| 制作结果 | 运行状态与转换 |
| --- | --- |
| idle / walk / drag / send | 使用已验收的帧、实际 fps/loop；face 根据原图实际正向及目标契约设置，不凭品种猜测。 |
| peek | 目标右侧隐藏的标准姿势；当前工具预览为左侧隐藏，需要对整个动作逐帧水平镜像一次。原始帧不改动，已经转换过的不能再镜像。loop=false。 |
| unpeek | 同一套运行时 peek 帧倒序，loop=false。 |
| edgehide | 已制作呼吸/眨眼时保留完整动态序列、fps/loop 和固定边缘；仅无动态停留素材时用运行时 peek 最后一帧静态保持，不取几乎全隐藏的首帧。 |
| speak | 基础形象的静态 PNG。base 不作为 anim 的动作名。 |

预览与产品的 edgehide/speak 循环参数不是同一个契约；显式设置运行参数，不能直接复制预览 manifest。保留 idleBreathing 的实际选择，避免把素材中已有的呼吸再叠加一遍。未生成 sleep/wake 等状态时记录缺失与目标 fallback；不把 fallback 宣称为新动作。当前标准状态和回退由 `animation-catalog` 定义。

当前入口仅支持 PNG，无 variants/realtime/renderer/model 字段；必须有 idle。每动作 1–256 帧，fps 大于 0 且不超过 60，face 为 ±1；包内最多 256 张去重帧、2048 个帧位置，原始 PNG 总量不超过 96 MiB、总像素不超过 160 MiPixels，每帧不超过 2 MiB、边长不超过 1024。描述符不超过 128 KiB，帧必须在包目录内且不能用软链接或目录穿越。512×512 是本技能的常用输出尺寸。制作规模越界时先用目标契约评估重采样并复验，不能为通过检查随意删动作。

有宿主源码时用 `companion-diy/local-2d-package` 的 readSource/validate 校验候选；无源码时走真实产品的导入反馈。`.petappearance` 是带版本的 gzip 数据包，不是普通 JSON 改后缀；推荐在导入成功后用产品“导出”取得便携包。kind=draft 只表示可继续编辑的草稿，不能换上桌面或声称成品。

## 导入、换上、即时生效

必须通过正在运行的目标客户端登记。独立 Node/Electron 进程写资料库，当前客户端的注册表与通知可能仍是旧状态，不算在线导入完成；不能让用户重启弥补。若已离线写入，在原客户端重走实际导入入口，不另启共享资料的实例。检查逐文件 imported/errors：ok:true 仍可能包含导入失败项。更新字节后按本次返回的新 id 应用，不按名称套用旧 id；在同一运行进程再次导入并确认实际新帧即时生效。

1. 核对目标运行实例、资料目录及任务授权。自动验证用隔离资料目录与首次绘制前隐藏的窗口；不为了导入另启一个共享日常资料的实例。
2. 从看板「更多 → 伙伴外观 → 导入形象」选择 `character.json` 或有效 `.petappearance`，读取成功/失败反馈，并确认库里出现正确名称和缩略图。数据型包通过受控入口进入用户外观库，不需要写入游戏目录、内置角色或手工复制到 plugins。
3. 打开预览逐一检查已有动作，再按已授权范围点击“使用形象”（旧版为“用这个形象”）换上。当前产品即时加载新帧，无需重启；它只改变当前伙伴的外观，不切换伙伴身份、名字、人设或记忆。仅导入收藏时不自动换上。
4. 检查真实桌宠的透明边缘、大小、待机/走路/抱起/带包裹动作，以及两侧探头、停留、缩回的连续性。朝向转换要在此验证，网页预览不能替代。确认外观确实来自本次素材，而不是旧帧或通用占位图。
5. 导出便携包，核对名称、动作参数与帧哈希；在隔离新实例导入验证。用隔离实例重启确认选择持久化，不能重启用户日常客户端作自动验收。重导入当前相同包应沿用库记录；若制作字节更新，重新核对返回的外观 id，再按授权应用。

## 与游戏、3D 形象的衔接

本次新做/改造的 Web 需要连续跟随换装时，使用 character:read 的 getAnimationCatalog/getAnimation 读取完整帧，另以 character:watch 的 watch/next/unwatch 贯穿页面生命周期。换装后完整解码再替换，保留角色位置和玩法进度；无需重启宿主。旧作品若未实现订阅，单列兼容限制。普通 HTML 不拥有插件专用 pet.pet.playAnim 或桌面窗口位移接口。

要把此形象用于游戏时，先核对游戏 SDK 的当前外观读取能力，再从产品真实入口打开大厅，验证读取的是换上后的外观。旧作品是否刷新取决于其读取/订阅机制，明确未迁移的兼容限制；本次新做/改造的 Web 按上段持续订阅，不以重新进入或开局代替。双人作品分别验证双方自己的当前外观。游戏 HTML 的目录导入另走游戏 skill 的流程，不将形象包当成 Vibe 游戏登记。

本技能输出是 2D 动作帧。实时 3D 模型、布偶数据和 renderer/plugin 包须按目标 3D 契约接入，当前本地 2D 入口会拒绝；不能用改后缀或打开 character3d 开关完成转换。需要真实 3D 时记录独立模型/渲染适配需求。

私人照片、原始生成图和形象包保留在用户授权位置；更新公开 skill 只提交流程/匿名夹具。导入本机不包含插件市场登记、向好友发送、公开素材、推送宿主或发版授权。
